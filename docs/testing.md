# Testing

Awash includes lightweight headless test and deterministic playtest runners. `tests/test_runner.gd` runs each test file listed in its `SUITES`, `TREE_SUITES` and `WORLD_SUITES`, in order; a new test file joins one of those lists.

## Run

```bash
./scripts/quality/test.sh
./scripts/quality/playtest.sh
```

## Current Coverage

What the tests and playtests cover, by topic:

- [The World and its Rooms](testing/world.md): the World's data, Plan and Map; what holds for every Room; each Region, its Background and tiles; and each Room's own tests and playtests.
- [The Player and combat](testing/player-and-combat.md): the Player's controller, rig and body; Health, Levels, Supplies and Equipment; and each enemy and Boss, their hits and sounds.
- [The game and its UI](testing/game-and-ui.md): starting the game, the Pause menu, music, dialogue and Interact; the Run; and the end-to-end playtests.

## File Ownership

- `scripts/core/input_setup.gd` owns input action setup and default bindings.
- `scripts/player/player_controller.gd` owns player state transitions, facing, and horizontal movement.
- `scripts/player/player_rig.gd` owns the Player's sprite frames, animations, sword visibility and placement.
- `scripts/player/player.gd` owns input reading, gravity and collision movement.
- `scenes/player/player.tscn` owns the player node structure and collision shape.
- `scripts/core/run_state.gd` (the `RunState` autoload) owns the Run: the current Room, the Entry the Player came through, and visited Rooms.
- `scripts/ui/pause_menu.gd` owns pausing and Panel switching; it pairs each `<Name>Button` in `%MenuButtons` with `<Name>Panel` in `%ContentRoot` by name, so a new Panel is a scene-only change. A Panel shows when its button takes focus; the script links the buttons' left and right neighbours round in a ring and points down to Resume. `scripts/core/input_setup.gd` adds W, A, S and D to Godot's `ui_` directions so menus move with the Player's keys.
- `scripts/core/world.gd` holds the World, reading its tables from `assets/world.json` (for the World editor to write; `docs/adr/0001-world-data-in-json.md`): every Region's record (its Map name and colour, theme and Backgrounds, keyed by the id that names its asset folder) and every Room's scene, where it sits, its Region, and its Exits and markers as the Map shows them, which callers ask for rather than reading its tables. Its Plan rides on the same records: a built Room that is to move carries a `plan` with its planned place, Region, Exits or markers, and a Planned Room has no scene, so the game leaves it out; `planned()` gives any Room as the Plan lays it out. `scripts/ui/map_layout.gd` lays the Map out, `scripts/ui/map_drawing.gd` draws a layout, and `scripts/ui/map_view.gd` draws the Map Panel from the World, the Run and the Player's position.
- `scripts/tools/draw_map.sh [--plan] [out.png]` draws the whole World as the Map draws it, every Room shown and each Region named; with `--plan`, as the World's Plan lays it out, Planned Rooms in outline, to see the World's shape before building it (`scripts/tools/draw_map.gd`). Like `draw_world.sh`, it opens a Godot window for a moment.
- The World editor (`tools/world-editor/`, started with `npm run world-editor`) has its own TypeScript checks and Vitest tests, run with `npm run world-editor:test` and in CI: it reads a Room scene's tile layers (their order, tile sets, offsets under their parents, see-through, and cells) and a Region's Background (its layers, how fast each scrolls and how often it repeats, their tile layers, plain colour fills and tints), places each Background layer for a Room as the camera frames each screen and traces a point back to the layer's cell through its repeat, says which Background a Room shows and which Rooms share it and a tile set's sources (sheets, which tiles collide or are one-way, and their tints); stacks a Room's layers front to back down through its Background, peeling away those in front of the one picked and marking the layers whose tiles collide from the real files; lays the World out as the Map does, as it is or as planned, walls with Exit gaps, screen lines and markers; edits the World as planned (adds, moves, resizes and removes Planned Rooms; moves a built Room only in its plan, which folds away when it comes back; adds an Exit with the one back next door, or a Drop with none; sets a Room's Region, marks and note; refuses to put two Rooms on one screen); writes `assets/world.json` back exactly as it is laid out; paints a tile layer (stamping a block of tiles picked from a sheet, filling or erasing an area, picking tiles back up with the eyedropper, all inside the Room) and writes a layer's tiles back into its scene, changing only that layer's line, encoding every layer of every Room exactly as Godot wrote it; builds a Planned Room's scene from a template (the Room script, a starter floor of its Region's ground along its bottom, open under a Drop; walls on sides with no Exit; an Exit for each of its Exits leading to the Entry it arrives by next door, named by side, and by screen when a side has more than one; an Entry for each way in, Drops into it included; the Player at the first), and refuses a built Room, a Region not ready to build in, or an Exit into no Room; reads only under `assets/` and `scenes/`, and writes only `assets/world.json`, Room scenes and Regions' Background scenes, never over a version that changed on disk since it was loaded; reads each test's result from a Check; and reads and writes its addresses: `/world` and `/plan`, each for the whole World or one Region (`/plan/undertow`), `/rooms/<room>`, `/tests`, and `?room=` for the Room selected, every view writing the address that reads back to it, and anything else unknown (`tools/world-editor/test/`).
- The Codex (`tools/codex/`, started with `npm run codex`) has its own TypeScript checks and Vitest tests, run with `npm run codex:test` and in CI: it reads a GDScript's literal consts and plain vars (numbers, strings, StringNames, calls such as preload, arrays, and dictionaries keyed by name or by value, over many lines, leaving comments and expressions alone) and a scene's nodes (parents, groups, the scene each instances, properties, external resources as their files and string arrays as strings); from the real repo it gathers each enemy's stats, drops (a Brinecap when it names none, and its Weapon), hits (from its scripts' damage or else its hitboxes', and the scenes it sends out), sheet and animations or the scene's grid, Rooms and lore, and lists enemies only in the docs as planned; each item's in-game effect, Shop price, Caches and the enemies that drop it, with planned items of their kind; story characters joined to the people of the Rooms with their sheets and lines; and each Region's Rooms, enemies, Caches, Rest points and shops; and works out the page's addresses, which entries its list shows by filter and search, and where each frame lies on a sheet; the page loads only files under `assets/` (`tools/codex/test/`).
- `scripts/tools/draw_world.sh [out.png]` draws the whole World as one picture, each Room drawn whole, placed by its cell, outlined and named (`scripts/tools/draw_world.gd`). It opens a Godot window for a moment, since a headless Godot draws nothing.
- `scripts/combat/health.gd` owns Health and invulnerability; `scripts/combat/hitbox.gd` and `scripts/combat/hurtbox.gd` connect a live Hitbox to the Hurtboxes it touches (`docs/specs/scavenger-spec.md` covers the Scavenger).
- `scripts/core/music.gd` (the `Music` autoload) owns the region music: it outlives scene changes, so a Room asking for the theme already playing lets it play on. Each Region's record in the World names its theme, and the Room script asks for it. The themes are made by `scripts/tools/make_music.py`, where each song is a block of data.
- `scripts/ui/dialogue.gd` owns how a conversation types out and advances; `scripts/ui/dialogue_box.gd` shows it, holds the Player still (`controls_locked`), and lets go a frame after closing so the closing press can't jump. `scripts/world/interactable.gd` is anything Interact can use: it watches for the Player on the `trigger` layer, shows the arrow prompt (`assets/ui/interact_prompt.aseprite`) while the Player can act, and reports being used; the Player body's `interact()` uses the nearest one in reach. `scripts/npcs/mara.gd` is Mara: her sprite (`assets/npcs/mara/mara_venn_1.aseprite`), her walk, and her Interactable, which opens her reminder lines. `scripts/story/intro.gd` plays the Intro in the first Room when `RunState.intro_pending` is set, which only the start screen's START does: it shows Blacktide stuck in the sand (`assets/regions/waking_coast/props/blacktide_stuck.aseprite`), has Mara carry it over, and hides it on the line cued `hand_over`.
- `scripts/core/room_exit.gd` owns crossing an Exit: it enters the next Room in the Run and swaps to that Room's scene from the Map.
- `assets/ui/awash_theme.tres` gives the menus the 5x7 pixel font (`assets/fonts/awash_pixel_5x7.png`, drawn in its `.aseprite`) and the game's palette. `assets/ui/awash_compact_theme.tres` sits inside it on the Pause menu's `CenterContainer` and the dialogue box's `Panel` and `Next`, swapping in the compact 3x5 font (`assets/fonts/awash_pixel_3x5.png`, drawn by `scripts/tools/make_font.py`) while the outer theme's styles still apply; the start screen and LEVEL UP keep the 5x7 font.
- `scripts/ui/stats_view.gd` lays the Stats Panel out as a two-column grid, each stat's name on the left and its value on the right.
- `scripts/core/main.gd` places the Player at the Run's Entry, using the Room's `Entries` markers (a new Run starts in `scenes/rooms/waking_coast_1.tscn`).
- `scripts/ui/start_screen.gd` owns the start screen (`scenes/ui/start_screen.tscn`, the main scene): PRESS START opens the START / QUIT menu, and START begins a new Run in the first Room. Its logo is drawn in `assets/ui/awash_logo.aseprite`. Its theme (`assets/ui/start_theme.wav`, made by `scripts/tools/make_music.py`) fades in a moment after the screen appears, loops on the `Music` bus, and fades out under the start chime.
